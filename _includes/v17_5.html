FIVE
EMERGING PATTERNS

AI 进入真实工作后，
反复出现的五个变化

过去七期不是七个独立话题，而是在持续追踪同一件事：AI 进入真实团队后，handoff、scope、decision rights、工程协作与 judgment 怎么移动。

01 / HANDOFF

先被压缩的，往往不是职位，而是原来的 handoff。

Designer → Figma → Engineer，开始变成 Designer → prototype / code → PR → Engineer review。

ROLE BOUNDARY COMPRESSION
02 / SCOPE

Scope 在扩大，价值却不会自动跟着扩大。

会 coding、会 prototype、会 research 的门槛都在下降。“做得出来”与“做得对”开始明显脱钩。

EXECUTION ↑ ≠ JUDGMENT ↑
03 / JUDGMENT

真正没有被解决的，仍然是 judgment。

复杂 context 里的优先级、trade-off、组织信息、业务约束，依然很难被压成一个稳定的自动化答案。

THE UNRESOLVED LAYER
04 / SYSTEM

瓶颈正在从“能不能生成”移到“能不能整合”。

真正卡住 production 的开始是 architecture、security、GDPR、design system、review ownership 与 maintainability。

GENERATION → INTEGRATION
05 / ORGANIZATION

AI adoption 最终是组织问题，不只是工具问题。

同一个工具，在一个团队里可以让 designer 开 PR；换一个组织，就可能被 compliance、流程或权责边界卡住。

SAME AI. DIFFERENT SYSTEMS.

SEASON 01 / SESSION CARDS

从“AI 会不会改变设计”，一路走到 implementation ownership、human judgment、Vibe Coding 与 production system。

001+
ORGANIZATION · SCOPE

设计师开始分化了

同样是 AI，不同组织里的设计师被推向完全不同的边界：有人开始进入 implementation，有人仍停留在传统 handoff；不同团队对 vision、MVP、质量和工程投入的取舍也完全不同。

SHIFT → 问题不再只是“AI 能做什么”，而是“不同系统会把设计师推向哪里”。
002+
VALUE · JUDGMENT

AI 之后，设计师还剩什么？

执行能力正在被拉平，但 framing、output evaluation、prioritization、trade-off 与复杂 context 下的判断没有同步被拉平。与此同时，AI 产品为什么“做出来了却没真正用起来”也开始进入讨论。

SHIFT → 执行变便宜以后，判断开始变成更稀缺的层。
